# Week 6 wireframe scope

Build low-fidelity, mobile-first wireframes for the **four task screens**, with exceptional states as variants of those screens—not as unrelated features.

1. **Choose game & rules:** game, edition, expansions, continue; unsupported edition state.
2. **Ask a rule:** concise question field, selected ruleset recap, submit; incomplete-detail clarification and error state.
3. **Answer & source:** answer, confidence/evidence status, rulebook title/version, passage preview, “Read source”; unresolved and conflicting-rules variants.
4. **Read source:** original passage, source location, back to answer; unavailable-passage variant.

**Interaction notes:** Explicit keyboard focus, accessible link names, source context, visible loading/retry/empty states, no reliance on color alone, no hypothetical user account or full game interface.

**Priority test:** Can a player answer an UNO +2 → +4 question and inspect the relevant rule text, or clearly recognize that the selected source cannot support a decision?

**Label check dependency:** Replace provisional wording using the results of three real label-comprehension participants before finalizing the wireframes.
